# How a group advances through waypoints

Consider four drones holding a square around a center at `(0, 0, 1.5)` m. If the center must travel 3 m to the right, moving each drone to a different independently chosen point can distort the square. A group waypoint instead moves the *center* while keeping each drone's assigned offset. For a 0.75 m first leg, a drone whose slot was at `(-0.5, -0.5, 1.5)` m targets `(0.25, -0.5, 1.5)` m. Its identity and slot do not change.

The route planner divides the 3 m center displacement into four equal legs and checks that all translated slots stay inside the declared task envelope. At 0.5 m/s, travel alone takes at least 6 s; each of four waypoint arrivals also requires 0.2 s of stable dwell. The 6.8 s sum is a lower bound, not a prediction, because acceleration, control error, formation motion, and downwash take time. The direct comparator changes only the maximum leg length from 0.75 to 3 m, producing one goal at the same final center.

A shared waypoint index avoids one drone rushing ahead while another is still recovering. The coordinator inspects all four assigned errors, pairwise separation, and speeds. If every drone meets the thresholds for 20 consecutive steps, it advances exactly one waypoint. If even one drone leaves its tolerance, the dwell count resets. A CPU test moves one drone 0.2 m away at the nineteenth step and confirms the group cannot advance. Other tests check speed, separation, exact final center, fixed slot offsets, direct-arm configuration, and rejected out-of-bounds routes.

The paper's phrase “sufficiently close” does not prescribe these numeric thresholds, and the student's one-step helper is not a complete group controller. Our explicit 0.15 m/20-step rule is a proposed task contract. The simulator now switches actor-visible and reward targets to the current translated slot during a reference flight. It records each world's gate state and each drone's actual position, target, velocity, action, and contact. The host audit reconstructs the sequence from saved rows. The physical 3 m route and matched direct comparator have now passed under deterministic reference control. C04 and C09 still need learned-policy execution, longer distances, and independent-seed reliability evidence. Synchronizing the index in a real decentralized swarm would use communication; a CPU counter alone is not radio traffic.

A small timing detail matters: the controller acts toward waypoint 0 at the command step. If all four drones pass its 20-step gate after a physics step, the *next* observation contains waypoint 1. The reward from the just-finished step still uses waypoint 0; reward progress memory is cleared before the new target so the target jump cannot create a fake progress reward. After the final waypoint is reached, the ordinary task success dwell must still complete. This lets the raw log separate route completion from stable mission completion.

The direct arm and waypoint arm can be compared only if their simulator image, task bundle, seed, controller, route endpoints, and all gate thresholds match. A host comparison checks those fields and permits only the maximum leg length to change. It reports each world's completion time and safety/error measures side by side. Four cloned worlds with the same seed are useful for detecting gross differences but do not count as four independent experiments; future seed variation is needed before making a reliability claim.

In the accepted 3 m flight, all four cloned worlds finished all four 0.75 m waypoints and the 200-step task success dwell. The direct 3 m arm also succeeded in all four worlds. The waypoint path took 11.88 s from command to outcome, compared with 9.66 s direct, and neither arm had a safety termination. This is useful evidence that the target-switch and group-gate code works in the actual physics loop. It does not show a waypoint advantage: the open-space direct path was already safe, and all worlds used the same seed. The [raw comparison](../docs/40-waypoint-route-contract.md) reports formation error and separation alongside timing.
